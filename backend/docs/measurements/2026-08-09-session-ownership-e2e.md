# 세션 소유권 거부 코드 E2E 실측 (ai-5)

- 일자: 2026-08-09
- 대상: `be/p3/tutoring` · 3-12(`INVALID_SESSION` 분리) 적용본
- 목적: P4 정산에서 **코드 기준으로만 서술**했던 `403/404` 를 실제 요청으로 확인해 `실측` 배지를 회복

## 배경

이전 실측표(`report/2026-07-30-API-실측결과.md`)는 소유자 불일치를 **`400 INVALID_SESSION`** 으로 기록했다.
그 코드는 **요청 본문 검증 실패에도 붙는 `C_001`** 이라 대시보드에서 오타와 세션 탈취 시도가 같은 버킷에 들어갔다.
3-12 에서 둘을 분리했으나 **실측표는 400 시절 값 그대로**여서 P4 에서 "재측정 필요"로 남겨 뒀다.

## 환경

Opener 인프라(앱 3개 제외) + `bootRun`. Postgres `accepting connections` ·
redis-auth `PONG` · chat 클러스터 `cluster_state:ok` / 노드 6.

사용자 2명을 `POST /api/auth/form-signup` 으로 만들고 **가입 응답 쿠키**를 그대로 썼다
(가입 경로도 `TokenIssuer` 를 지나므로 토큰이 발급된다 — 3-5 가 참임을 이 절차 자체가 보여준다).

## 결과

| # | 시나리오 | 요청 | 기대 | 실측 | 판정 |
|---|---|---|---|---|---|
| 1 | **대조군** — 정당한 소유자 연결 | `GET /api/chat/connect?sessionId=777777` (x1) | 200 + SSE | **200** · `content-type: text/event-stream` · `event:connected` 수신 | ✅ |
| 2 | **타인 세션 접근** | `POST /api/chat/save-message` `{sessionId:777777}` (x2) | 403 | **403** `C_013` `세션 접근 권한이 없습니다.` | ✅ |
| 3 | **없는 세션 접근** | `POST /api/chat/message` `{sessionId:999999}` (x1) | 404 | **404** `C_014` `세션을 찾을 수 없습니다.` | ✅ |

응답 본문(2번):
```json
{"code":403,"data":null,"error":{"reason":"세션 접근 권한이 없습니다.","code":"C_013"},
 "message":"세션 접근 권한이 없습니다.","status":"error"}
```

## 확인된 것

1. **인가 실패(403)와 대상 부재(404)가 실제로 갈린다.** 둘 다 `C_001`(400)로 나가던 상태가 해소됐다.
   이제 *"남의 세션 접근 시도"* 에만 알림을 걸 수 있다.
2. **거부가 소유자 불일치에 한정된다.** 대조군인 정당한 소유자는 200 으로 통과하므로,
   과차단(모두를 막아 놓고 "방어했다"고 말하는 것)이 아니다.
3. **어드바이스(`@RequireSessionOwner`)가 실제로 건다.** 2·3번 요청 모두 어드바이스 경유 경로다.

## 부수 확인 — refresh 수명 통일(3-5)

가입 로그에 `[Auth] 토큰 발급 완료 - refreshTtl: PT336H`.
**336시간 = 14일**로, JWT `exp`·Redis TTL·쿠키 `maxAge` 가 하나의 설정값에서 계산된다는 3-5 의 결과가
실행 중 로그로 확인된다(이전에는 JWT 14일 / TTL·쿠키 7일로 갈라져 있었다).

## 남은 것

`report/2026-07-30-API-실측결과.md` 의 400 기록은 **그대로 두고 이 문서를 병기**한다 —
당시 측정은 그 시점 코드에 대해 참이었고, 지우면 변경 이력이 사라진다.
