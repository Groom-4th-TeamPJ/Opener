### 지적 5건 처리

1. **대안 비교 보강** — 이커머스 5에 저장소 후보 셋 비교 항목 신설(DB 스케줄 테이블 / Quartz JDBC JobStore / Redis ZSet), 휠 파인더 2의 라우팅·compose·CI 세 항목에 각각 대안과 탈락 사유 삽입(별도 도메인·서브도메인의 CORS·SameSite 비용, Jenkins의 CI 서버 추가 운영). **실제로 당시 비교했다고 단정하지 않고 "선택이 성립하는 근거" 형태로 서술** — 검증 불가능한 과거 행위를 사실로 주장하지 않기 위함.
2. **측정 한계 명시** — 휠 파인더 2 결과에 "결과는 전부 정성, 개선 폭 미측정 + 도달 가능한 상한(Actions 실행 시간은 이미 기록됨)" 추가.
3. **튜터링 4 진단 시점 명시** — `근본 원인을 …로 보고`를 `당시에는 …로 진단하고, 그 전제 위에서`로 바꾸고, 스윕이 그 진단을 반증했다는 항목을 뒤에 신설(중앙값 0.40 · 최대 0.53). 해결 과정과 결과의 모순 해소.
4. **부정 서술 분산** — 한 항목이 주장→즉시 철회를 반복하던 구간을 "한 일"과 "한계"로 분할. 이커머스 1의 1·3·6번, 튜터링 5의 2번 → 각 2항목으로. 이커머스 1은 7항목 → 10항목.
5. **오타·정합 3건** — `/actuator/env에도 안 미노출` → `미노출`(개조식 변환 잔재), 휠 파인더 소개의 `아래 두 사례` → `세 사례`, 튜터링 소개의 `아래 5개 기능` → `7개 사례`, 이커머스 소개의 `4개 기능` → `추첨 예약 포함 5개 기능`. 뒤 세 건은 **절 수와 소개 문구가 원래부터 어긋나 있던 것**으로, 절 추가 과정에서 드러남.

## 3. 면접관 관점 추가 지적

### 3-1. 대안 비교가 없는 절 2개

사용자가 정의한 해결 과정의 형태(대응 → 측정 → 대안 → 선택 근거) 기준.

- **휠 파인더 2 (Nginx · 배포)** — 5개 항목 전부 "했다" 서술. 대안도 측정도 없음. Nginx 대신 무엇을 검토했는지(별도 도메인 + CORS 허용, API Gateway), GitHub Actions 대신 무엇이 있었는지가 없어 결정한 흔적이 안 보임. 13개 절 중 가장 약함.
- **이커머스 5 (추첨 예약)** — "왜 Redis Sorted Set인가"의 대안이 없음. DB 스케줄 테이블 폴링 · Quartz · 같은 저장소가 이미 쓰는 Kafka Streams Punctuator 세 후보가 자연스러운 비교 대상인데, 마지막 항목에서 "쿠폰 자동 비활성화와 정반대 선택"이라고만 인정하고 왜 그 선택이었는지는 미서술.

### 3-2. 측정치가 없는 절 3개

수치가 하나도 없는 절 — 휠 파인더 1 · 휠 파인더 2 · 튜터링 6. 튜터링 6은 테스트 5개로 경계를 고정했다는 근거가 있어 상대적으로 낫고, 휠 파인더 2개 절은 정성 서술뿐. 면접에서 "그래서 얼마나 좋아졌나"에 즉답 불가.

### 3-3. 튜터링 4의 진단이 본문과 결과에서 어긋남

해결 과정 3번(현재)은 `근본 원인을 한국어 질문과 영어 중심 임베딩 모델의 언어 정렬 문제로 보고 대안 셋을 비교`라고 현재 판단처럼 서술하는데, 결과 2번은 스윕 실측으로 `0.7이 코퍼스에서 도달 불가한 값이라 검색 0건은 필연`임을 확인해 그 진단을 반증함. 면접관은 해결 과정을 먼저 읽으므로 "틀린 진단을 근거로 대안을 고른 사람"으로 읽힐 위험. 해결 과정 쪽을 `당시에는 ~로 진단했고, 이후 스윕으로 반증됨`처럼 시점을 명시하는 편이 안전.

### 3-4. 부정 서술의 밀도

`부재 · 미성립 · 미획득 · 제외 · 불가 · 미도입`이 한 항목에 3~4회 겹치는 구간이 이커머스 1(선착순), 튜터링 4·5에 몰림. 정직성은 강점이지만 한 항목 안에서 주장 → 즉시 철회가 반복되면 "한 것"보다 "못 한 것"이 먼저 읽힘. 항목당 한계 인정은 1회로 제한하고 나머지는 결과·회고로 미루는 편을 권고.

### 3-5. 항목 하나가 지나치게 긺

이커머스 1의 3번·6번, 튜터링 5의 2번은 한 `<li>`가 300자를 넘어 면접관이 한 호흡에 못 읽음. 내용을 줄이지 않고도 항목을 2개로 쪼개면 읽힘.
