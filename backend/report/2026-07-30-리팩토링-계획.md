## 1. 포트폴리오 주장 vs 코드 실제 — 논리적 비약 진단

STAR 5개를 코드와 1:1 대조했다. **면접에서 한 번만 파고들면 무너지는 지점**을 심각도순으로 정리한다.

### 비약 A — "Spring WebFlux" 라고 썼지만 서블릿 스택이다 (치명)

| 포트폴리오 | 코드 실제 |
|---|---|
| `tech: [..., "Spring WebFlux", ...]` | `build.gradle:33` 에 `starter-web` 동시 존재 → **Tomcat 서블릿 스택** |
| "컨트롤러가 `Flux<ServerSentEvent>` 를 직접 반환" | 맞다. 단 MVC 의 `ReactiveTypeHandler` 가 async 요청으로 처리하는 것 |
| — | `application.yml:59-66` 의 `server.servlet.context-path`·`server.tomcat.mbeanregistry` 가 서블릿 스택임을 확정 |

**왜 위험한가**: "WebFlux 쓰셨네요, Netty 이벤트 루프 몇 개로 도나요?" 한 마디에 무너진다.
**해소 방향**: 두 갈래 중 하나.
- (선택) 표현을 **"서블릿 스택 위 Reactor 논블로킹 스트리밍"** 으로 정정 → 정직하면서 오히려 더 어려운 주제(하이브리드)로 승격
- (미선택) 진짜 WebFlux 전환 → JPA·Security 전면 재작성이라 범위 초과

→ **선택: 표현 정정 + 코드가 그 표현에 부합하도록 보강**(비약 B 해소)

### 비약 B — "스레드 점유와 연결 수명을 분리했다"면서 이벤트 루프를 블로킹한다 (치명)

STAR 1 의 핵심 주장이 코드와 **정면 충돌**한다.

| 위치 | 블로킹 |
|---|---|
| `ChatServiceImpl.java:394-405` | `doOnComplete` 안에서 **JDBC 트랜잭션** |
| `ChatSessionStateMachineService.java:59` | `sendEvent(...).blockLast()` |
| `ChatServiceImpl.java:284,388` | Lettuce 동기 `saveMessage` |

논블로킹을 주장하면서 콜백에서 블로킹하면, 스레드를 아낀 효과가 상쇄된다.
**해소**: 부수효과를 `boundedElastic` 으로 오프로딩 (§4-C)

### 비약 C — "동시 연결 확장"인데 인스턴스 1대가 한계다

`ChatServiceImpl.java:81` 의 `sinks`, `ChatSessionStateMachineService.java:27` 의 `machines` 가 **인메모리 Map**.
세션 데이터는 Redis 에 있는데 전달 경로와 상태만 JVM 로컬이라 스케일아웃이 불가능하다.
**해소**: 이번 범위에서는 **한계를 명시적으로 문서화**하고 확장 설계를 제시(코드 변경 없음).
"어디까지 했고 다음이 무엇인지 아는 것"도 평가 대상이다.

### 비약 D — "관측 체계 구축"인데 로그 레벨 설정이 3개 파일 모두 죽어 있다

`application.yml:49`, `application-prod.yml:47`, `application-dev.yml:132` 의 `logging.level` 이
전부 엉뚱한 부모 키 아래로 들어가 **미적용**. SSE 30분 타임아웃(`application.yml:55`)도 마찬가지.
**해소**: §4-B

### 비약 E — 보안 주장이 없는데, 실제로는 인증 결함 3건이 살아 있다

포트폴리오에 보안 STAR 가 없다. 그런데 코드에는:
- 블랙리스트가 **쓰기만 있고 읽기가 없는 死 코드** (`AuthServiceImpl.java:141` 단 1곳)
- `logout()` 이 `refreshToken:{userId}` 를 **삭제하지 않음**
- **SSE Sink 하이재킹** — 남의 대화가 공격자에게 스트리밍됨

**이건 위기가 아니라 기회다.** 고치면 STAR 하나가 새로 나온다 (§3).

### 접근 부족 F — 대화 히스토리에 윈도우가 없다

`ChatRedisServiceImpl.java:136` 이 `range(key, 0, -1)` 로 전체를 반환.
턴 수만큼 프롬프트가 선형 증가 → 비용·TTFT 악화. RAG 품질을 논하면서 컨텍스트 관리가 없다.

### 접근 부족 G — 테스트가 0건이다 (chat/auth)

가장 복잡하고 방금 리팩토링한 영역에 테스트가 없다.
`build.gradle:103` 에 `reactor-test` 를 추가해 뒀으나 사용처가 없다.
