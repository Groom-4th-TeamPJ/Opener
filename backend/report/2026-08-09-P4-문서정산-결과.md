## 1. 한 줄 결론

**감사가 지적한 것을 코드가 따라잡은 섹션은 주장이 강해졌고, 따라잡지 못한 섹션은 수치가 철회됐다.**
같은 감사인데 결말이 갈린 유일한 변수는 *"그 사이 코드를 고쳤는가"* 다.
문서 정산을 코드 작업 뒤에 두라는 마스터플랜 §4 순서 규칙이 실제로 값을 했다.

| 유형 | 섹션 | 대표 사례 |
|---|---|---|
| **참으로 만들기** (코드가 따라잡음) | ai-1 · ai-2 · ai-5 · eco-3 | ai-5: *"전수 대조를 했다"* → **"대조가 4경로 중 3경로의 저장 누락을 잡았다"** |
| **철회·강등** (코드가 못 따라감) | ai-4 · eco-2 · eco-4 | ai-4: `32% → 8%` **실측 배지 삭제**(원자료 부재) |

## 3. 섹션별 처리

### 4-4 ai-1 (SSE / VT / Flux)

**핵심은 문제 원인을 두 축으로 쪼갠 것이다.** ①바운디드 풀 고갈(VT 가 해결) ②`blockLast()` 완료 대기(Flux 가 해결).
커밋 순서상 VT 가 먼저이므로 한 인과로 묶으면 `git log` 한 번에 무너진다.

- **참으로 만듦** — 버퍼 오버플로 시 연결 종료(`SSE_BUFFER_SIZE=256` 명시) · 상류 구독 `Disposable` 3지점 정리
- **정정** — SVG 저장 경로가 자동 발행처럼 그려져 있었다 → `POST /chat/save-message` 트리거 명시
- **교체** — 코드카드를 컨트롤러에서 `emitEvent` 오버플로 처리로. **본문의 가장 위험한 주장 옆에 반증 가능한 코드**를 두는 원칙
- **추가** — VT 가 있는데 Reactor 를 또 쓴 이유(Spring AI `ChatClient.stream()` 이 `Flux` 만 반환 = **API 제약**), 조립 구간 블로킹 잔존

### 4-5 ai-2 (Redis Cluster)

**한계 4건 추가가 본체다.**

- **참으로 만듦** — *"대화 맥락이 지연을 흡수"* 삭제 → 3-4 의 지점별 3분기 라우팅 + 3-3 의 질문 보장을 **층이 다른 두 방어**로
- **강등** — Hash Tag 는 *"CROSSSLOT 을 막았다"* 가 아니라 **멀티키 연산이 하나도 없는 상태에서의 선제 조치**
- **정정** — failover 대응의 실체는 `testOnBorrow` 가 아니라 `ClusterTopologyRefreshOptions` + `REJECT_COMMANDS` / *"연결 제한 없이"* → **20개 풀로 100 VU**
- **추가** — 7초의 출처(`cluster-node-timeout 5000`) · `cluster-replica-validity-factor 0` · `maxmemory 256mb` + `allkeys-lru`

### 4-7 ai-4 (RAG) — 가장 많이 깎인 섹션

- **삭제** — `32% → 8%` (§2)
- **정정** — SVG 분기축이 코드와 정반대였다. 축은 `app.rag.enabled` **하나**이고 켜져 있으면 **일반 채팅도 매 턴 검색을 경유**한다
- **정정** — *"기본값 0.7"* (실제 Spring AI 기본값은 **0.0**) · *"Top-K 5 로 제한"* (기본값 **4** 보다 크다) · `fetch join` (0건, 실제는 **DTO 프로젝션**)
- **정정** — 모델 교체가 *"비용 때문에 보류"* 가 아니라 **경로 자체가 없음**(차원·스키마·색인 스킵 조건 3곳 동시 수정 + 전량 재적재)
- **범위 명시** — `80ms` 의 모집단(오프너 경로 한정)과 통계량(p95) · 조건부 빈은 **플래그를 꺼봤을 때 드러난 기동 실패**

### 4-8 ai-5 (인증·세션) — 유일하게 주장이 강해진 섹션

P3 가 결함을 실제로 고쳐서 **정산이 승격이 됐다.**

- 전수 대조 → **대조가 결함을 잡았다**(발급 4경로 중 3경로 저장 누락 + 수명 3중 불일치 → `TokenIssuer` 단일화)
- *"세션 초기화 안쪽 단일 통과점"* → **판정 / 진입 통제 분리**(`@RequireSessionOwner`), 6곳 → 어드바이스 1 + 근거 있는 예외 2곳
- `400 C_001` → **403 / 404** 분리. `permitAll` 의 `/test/**` 미인증 공개 정리
- **삭제** — self-invocation 설명(`initializeSession` 에 `@CircuitBreaker` 가 애초에 없어 공회전)
- **추가 한계 4건** — refresh 회전·재사용 탐지 부재 · access 사용자 단위 폐기 불가 · **로그아웃 5변형이 HTTP 200 만 봤음** · `initializeSession` 서킷 미적용

### 4-2 eco-2 (재고) — ◐ 부분 완료

재측정(P2 Task 4·5·7)이 보류라 **실측 불요 항목만** 집행했다.

- **정정** `maxAttempts=30 → 3`. *"격차를 근거로 올렸다"* → **"올리지 않은 이유"**(한도를 키우면 실패가 지연으로 바뀌어 결제 응답에 얹힌다)
- **철회** A/B 수치. 메커니즘만 남기고 `재측정 대기` 배지
- **승격** 조건부 UPDATE 가 *"1순위로 남겼음"* → **전략 3종 구현 완료, 실측만 남음**. 주제가 *"낙관적 락을 적용했다"* → *"대안을 구현해 재서 고른다"* 로 이동
- **추가** 대조 배치의 방향·지속성 2축 판정과 *"자동 보정을 하지 않는 이유"*

### 4-3 eco-3 / eco-4

**eco-3** — 2-9(트랜잭션 분리) · 2-7(취소 전용 회로) · 2-8(전이표)이 서술을 참으로 만들었다.
개요의 *"분산 락은 배치의 배타 실행에만"* 도 **쿠폰 보정 배치 한정**으로 좁히고, 결제 보상 배치엔 락이 없다는 사실을 노출했다.

**eco-4** — 코드카드를 실물(`CouponDelayProcessor` / `delay-events-store` / `CouponDelayEventListWrapper`)로 교체하고
구 `Transformer` → 신 Processor API 이관 경위를 남겼다. 한계 4건 추가(상대 지연이라 재처리 시 **타이머 리셋** ·
`delayMillis<=0` 조용한 드롭 · `WALL_CLOCK` 비결정성 · 리밸런싱 중복이 **fencing 밖의 DB UPDATE**).

## 5. 남은 것

### 5.1 4-2 를 `☑` 로 닫으려면

**P2 Task 4·5·7 실측**이 필요하다. 인프라 배타 사용이라 Opener 를 내리고 groom 을 올려야 한다.
채워야 할 자리는 두 곳 — 지터 A/B(**VU 를 고정한 조건으로**)와 차감 전략 3자 비교.

### 5.2 배지를 되찾을 수 있는 항목

| 항목 | 필요한 것 |
|---|---|
| ai-1 TTFT | 3-9 (OpenAI 키) |
| ai-4 임계값 근거 | 3-10 골든셋 + 스윕 (OpenAI 키, 임베딩 24회) |
| ai-5 `403/404` E2E | 인프라 기동 후 재측정 — **코드는 이미 403/404 인데 실측표가 400 시절 값이다** |

**압축은 했다** — ai-5 는 12항목 2,941자 → 8항목 2,073자(**−30%**), eco-2 12→9항목, ai-4 10→9항목으로 병합했다.
그래도 밴드에 못 들어간다.

**여기서 더 깎지 않기로 한 근거는 §5 다.** 분량 밴드는 애초에 **미구현 To-Be 서술이 부풀리는 것**을 잡으려는 기준이었고,
지금 늘어난 것의 성격이 다르다.

1. **구현을 마친 작업의 근거** — ai-5 의 `TokenIssuer`·어드바이스, eco-3 의 트랜잭션 분리·전이표처럼 실제로 코드가 있는 것들
2. **철회 사실 자체의 서술** — *"이전 판본은 X 라 적었으나 근거가 없어 철회했다"* 는 문장은 **정직성의 증거라 지우면 손해**다
3. **범위 명시 문장** — *"모집단은 오프너 경로"*, *"코드 기준이고 실측표는 갱신 전"* 같은 것

**즉 이번 초과는 드리프트 신호가 아니라 정산의 부산물이다.** 밴드는 유지하되,
다음 분량 조정은 **재측정으로 수치가 채워져 "철회했다" 설명 문장을 지울 수 있게 된 뒤**에 하는 것이 맞다.
그때 2·3번 성격의 문장이 자연스럽게 빠진다.

### 5.4 범위 밖으로 남긴 것

`PORTFOLIO.html` 은 자체 라이트 테마(`--bg-page:#f8f9fb`)를 쓰고 code-card 는 다크 배경(`#1e1e2e`)이다.
글로벌 `html-docs` 의 sketch 테마와 다르다. **전면 테마 전환은 P4(사실 정산) 범위가 아니라 별도 결정 사항**이라 손대지 않았다.
