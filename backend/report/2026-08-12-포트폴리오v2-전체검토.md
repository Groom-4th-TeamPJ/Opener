## 2. 수정 대상

### [중] SVG #5 — 라벨이 박스 위로 올라탐

`PORTFOLIO_v2.html:1212` · 사례 4(채팅 Redis) "실제 동작 구조 — 인증 요청과 채팅 요청이 흐르는 Redis 경로"

```
1212  <text class="v-tag" x="205" y="195">② GET /chat/connect, POST /chat/message</text>
1217  <rect class="rc-box-y" height="50" rx="8" width="190" x="450" y="175"/>   ← Master 박스
1218  <text class="rc-tt" x="545" y="195">Master</text>
```

라벨은 `start` 앵커 · bold 12px · 38자라 실제 폭이 약 250px → **x 205~455 를 차지**. Master 박스 좌변이 **450**, 세로도 `y=195`가 박스 범위(175~225) 한가운데라 정면으로 겹침. 렌더에서 `POST /chat/message` 의 뒷부분과 `Master` 글자가 서로 뭉갬.

같은 도해의 ① 라벨(`① POST /form-login`)은 박스가 없는 y 대역이라 문제없음 — ②만 결함.

**처방 후보**: 라벨을 박스 위쪽 여백(`y≈165`)으로 올리거나, 라벨을 `② GET /chat/connect · POST /chat/message` 두 줄로 나누거나, Master 열 전체를 오른쪽으로 40px 이동.

### [중] SVG #6 — 범례 항목끼리 겹침

### [하] 서킷 서술의 "세 지점"이 모호

사례 5 해결 과정: *"세 지점을 같은 값으로 맞추지 않은 이유는 호출 특성이 다르면 서킷 정책도 달라야 한다고 봤기 때문"*

실제 설정은 **LLM 3개(`llm-chat`·`llm-rag`·`llm-summary`)가 완전히 동일한 값**이고 `redis-chat` 하나만 차등화돼 있음. 앞 문장에서 "4개 지점"이라고 세어 놓고 여기서 "세 지점"이 나오므로 면접관이 개수를 되물을 여지가 있음. `네 지점 중 캐시 하나만 값을 달리한 이유는…` 정도로 맞추면 코드와 정확히 일치.

## 3. 코드 쪽 드리프트 1건

`src/main/resources/application-dev.yml:161`

```yaml
similarity-threshold: 0.2        # 유사도 임계값 - 영어 문서 + 한국어 쿼리는 유사도가 낮음
```

주석이 **포트폴리오가 스윕 실측으로 반증했다고 서술한 그 진단**(영어 자료 + 한국어 질문)을 그대로 유지하고 있음. 문서는 "적재 자료에 영어 문서 자체가 부재"라고 정정했으므로 둘이 정면으로 어긋남. 면접에서 저장소를 함께 보는 상황이면 바로 드러나는 종류.

**처방**: 주석을 실측 결과로 교체 (예: `# 스윕 실측 기준 - 질문 20문항 최고 유사도 중앙값 0.40, 0.3 이상은 검색 0건`).

> 이 항목은 코드 수정이라 이 보고서에서는 지적만 하고 손대지 않음.
