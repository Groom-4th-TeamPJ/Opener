### 0-2. 절대 하지 말 것

- **정직성 자체를 줄이지 않는다.** 이 문서의 유일한 차별점이 여기에 존재. 바꾸는 것은 정직성의 **위치와 형식**
- 유보를 삭제하는 것이 아니라 **결과 문장 본체에서 각주·접힘으로 이동**

## Task 2 — `JwtUtil` access 쿠키 maxAge 설정값화 + `ai-5` 서술 동반 갱신

**우선순위:** 2 · **비용:** 20분 · **분류:** 코드 수정 + 문서 동반

### 목적

`ai-5` 의 핵심 서사가 **"수명 3중 불일치를 발견해 설정값 하나로 통일"** 인데,
**같은 파일 두 줄이 그 서사와 정면 충돌**하는 상태로 잔존. 면접관이 코드를 열면 즉시 노출.

### 사실 (확인 완료)

```
backend/src/main/java/spring/backend/shared/infrastructure/security/util/JwtUtil.java:166
    .maxAge(Duration.ofMinutes(60)) // 수명 : 1시간          ← 리터럴
backend/src/main/java/spring/backend/shared/infrastructure/security/util/JwtUtil.java:177
    .maxAge(Duration.ofMillis(refreshTokenExpiration))       ← refresh 는 이미 설정값
backend/src/main/java/spring/backend/shared/infrastructure/security/util/JwtUtil.java:192
    .maxAge(Duration.ofMinutes(60)) // 수명 : 1시간          ← 리터럴
```

문서 스스로 자백한 상태 — `ai-5` 해결 과정: *"통일한 것은 refresh 축뿐 — access 쿠키의 maxAge 는
아직 60분 리터럴이라 설정을 바꿔도 쿠키만 미반영(지금은 두 값이 우연히 같아 증상이 부재)"*

### 작업

1. `JwtUtil` 에서 access 토큰 만료 설정값 필드를 확인 (`refreshTokenExpiration` 과 짝이 되는 것)
2. 166 · 192 행을 `.maxAge(Duration.ofMillis(accessTokenExpiration))` 형태로 교체
3. 주석을 값 중복 서술이 아니라 **근거 서술**로 교체 (마침표 없이, 단답식)
   - 예: `// JWT exp 와 같은 설정에서 계산 — 세 수명이 어긋나면 재발급이 조용히 실패`
4. **포트폴리오 `ai-5` 의 자백 문장을 동반 수정.** 코드가 고쳐졌으므로 그 문장은 이제 거짓
   - `다만 통일한 것은 refresh 축뿐 …` 이후 전체를 삭제하고
   - 앞 문장의 `셋 다 설정값 하나에서 계산하게 통일함` 을 **access·refresh 양축**으로 확장 서술

### 검증

- `rtk proxy grep -n "ofMinutes(60)" backend/src/main/java/.../JwtUtil.java` → **0건**
- `cd backend && ./gradlew test --tests "*JwtUtil*"` (테스트 존재 시)
- 인자 없는 `./gradlew test` 금지 — `BackendApplicationTests` 가 Docker 없이 실패

### 함정 (중요)

**코드와 포트폴리오는 동반 수정.** 이 저장소에서 포트폴리오는 명세 역할이라, 코드만 고치면
문서 서술이 거짓이 되고 문서만 고치면 코드가 서술을 배신. 두 편집을 **한 커밋**에 넣는다.

## Task 8 — 자백 서술 전부에 Q5 패턴 적용

**우선순위:** 8 · **비용:** 2~3시간 · **분류:** 문서

### 목적

**자백을 감점에서 가점으로 전환하는 유일한 방법.**
현재 문서의 자백은 대부분 `"못 했음"` 에서 종료. 유일하게 성공한 `eco-1` Kafka RF=1 서술은
자백을 **3층으로 분류**했기 때문에 면접에서 방어 가능.

### Q5 패턴 정의

> **지금 위치 X** → **도달 가능한 상한 Y** → **둘을 가르는 것 Z**

`eco-1` 원문 (모범 사례, 그대로 유지):

> Redis 탈락 사유를 그대로 적용하면 지금의 Kafka 도 같은 등급 — 장애 시 순서 보존은 둘 다 못 함(**X**).
> 가른 것은 현재 상태가 아니라 도달 가능한 상한 — Kafka 는 `RF≥3 · acks=all · min.insync.replicas=2` 로
> **설정만 바꾸면** 그 속성을 얻지만(**Y**), Redis 는 복제가 비동기이고 재생 가능한 로그가 없어
> **어떤 설정으로도 얻지 못함**(**Z**)

### 적용 대상 (우선순위 순)

| # | 자백 위치 | 현재 상태 | Z 후보 (직접 확인 필요) |
|---|---|---|---|
| 1 | `wf-2` 결말 — `blacklist:user:{id}:version` 미이관으로 폐기 단위 후퇴 | 자백만 · **근거 부재** | 비밀번호 변경 기능 부재로 요구 미발생 / jti 키 위에 version 축 확장 가능 |
| 2 | `eco-5` — `@Scheduled` 3개 배타 실행 장치 부재 | 자백만 | eco-1 이 정한 기준(저빈도·긴 임계 구역·큰 피해)에 셋 다 해당 → 적용 대상 확정 · 미착수 |
| 3 | `eco-1` — 결제 보상 배치에 분산 락 부재 | 자백만 | 쿠폰 보정 배치에 이미 적용한 것과 같은 형태로 이식 가능 |
| 4 | `ai-4` — 청킹 미검토가 "이 절의 가장 큰 공백" | 자백만 | 다국어 정렬 진단과 독립인 축 · 스플리터 인자 지정만으로 실험 가능 |
| 5 | `ai-1` / `ai-3` — SSE 전달 맵이 인스턴스 로컬 | `wf-1` 과 대비만 | wf-1 에서 이미 Pub/Sub 로 푼 문제 · 같은 처방 이식 경로 존재 |
| 6 | `eco-4` — EOS 경계 밖 DB 쓰기, 재처리 횟수 관측 불가 | 자백 + 처방 언급 | `WHERE is_active = true` 한 줄 (문서가 이미 Z 를 적음 — 형식만 정리) |

### 규칙

- **Z 를 지어내지 않는다.** 실제로 확인한 것만. 확인 못 하면 그 자백은 X 로 두고 넘어감
- Z 는 "하면 된다"가 아니라 **"무엇이 그것을 가능/불가능하게 하는가"** — 구조적 근거

### A-3. 임계값 스윕 (Task 14) — 측정 완료 2026-08-09

**측정 방법.** 앱을 거치지 않고 pgvector 에 직접 질의.
Spring AI `PgVectorStore` 와 같은 기준(`similarity = 1 − cosine_distance`, `similarity ≥ threshold` 통과 후 `topK` 절단)을
재현하고, 질문 임베딩은 운영과 같은 `text-embedding-3-small` 로 생성.
스크립트: `backend/report/threshold_sweep.py` · 질문 20문항 · `topK=5`.

**질문셋.** 벡터 스토어의 `metadata->>'type'` 7종에 맞춰 한국어 질문 20문항을 배치하고,
각 질문의 **기대 type 을 정답 라벨**로 고정(예: *"원의 넓이를 구하는 공식이 뭐야"* → `Geometry`).
채점 기준표가 없던 상태를 이 라벨로 대체 — 사람이 관련성을 판정하지 않고 **문서 자신의 분류를 정답으로 사용**.

**결과 (n=20 · topK=5)**

| 임계값 | 검색 0건 질문 | 평균 검색 건수 | 재현율(정답 type 1건 이상) | 정밀도(통과 문서 중 정답 type 비율) |
|---|---|---|---|---|
| 0.0 | 0/20 | 5.00 | 17/20 = **85%** | 37.0% |
| 0.1 | 0/20 | 5.00 | 17/20 = **85%** | 37.0% |
| **0.2 (현재 설정)** | 0/20 | 5.00 | 17/20 = **85%** | 37.0% |
| 0.3 | 1/20 | 4.55 | 16/20 = 80% | 36.3% |
| 0.5 | **19/20** | 0.25 | 1/20 = 5% | 20.0% |
| **0.7 (원래 값)** | **20/20** | 0.00 | 0/20 = **0%** | 0.0% |

**최고 유사도 분포 (질문별 1위 문서)** — min **0.2754** / 중앙값 **0.4039** / max **0.5293**.
20문항 중 **0.7 을 넘는 질문이 0개**이고 0.5 를 넘는 것도 1개.
→ *"임계값 0.7 에서 검색 0건"* 이 우연이 아니라 **분포상 필연**임이 확인됨.

**세 가지 판정**

1. **원래 값 0.7 은 이 코퍼스에서 구조적으로 불가능한 값.** 어떤 질문도 도달하지 못하므로 RAG 가 항상 무효
2. **현재 값 0.2 는 0.0·0.1 과 결과가 완전히 동일.** `topK=5` 가 먼저 차서 임계값이 실질 무작동 —
   즉 **지금 설정에서 임계값은 사실상 "끄기"와 같다.** 유효한 상한은 0.3 부근에서 시작
3. **정밀도는 전 구간 37% 언저리에서 임계값에 거의 반응하지 않음.** 임계값을 올려도 관련 없는 문서가
   걸러지는 게 아니라 **문서 자체가 사라짐**. 정밀도를 올리려면 임계값이 아니라 다른 축(청킹·리랭킹)이 필요

**A-3 보강 — 자료의 실제 성격 확인 (2026-08-09, 사용자 확인 D-11)**

사용자 확인 결과 **적재 자료에 영어 문서는 처음부터 부재**했고, 내용은 **수학 모의고사 문제**이며
원본은 **텍스트 + 그림 조합**. 이에 맞춰 코퍼스를 다시 조사.

| 항목 | 값 |
|---|---|
| `[asy]` (Asymptote 그림 소스) 포함 청크 | **787건 / 5,799 = 13.6%** |
| 그 청크의 평균 길이 | 963자 |
| 그중 `[asy]…[/asy]` 블록의 평균 길이 | 458자 |
| **청크 내 그림 코드 비중** | **평균 47.1%** |

즉 **그림이 이미지가 아니라 좌표·`draw`·`label` 명령의 소스 코드 텍스트로 적재**돼 있고,
그런 청크는 **절반이 그 코드**. 질문은 자연어 한 문장이므로 형식 비대칭이 크다.

**다만 이 축이 원인이라고 단정 불가.**

| 지표 | 값 |
|---|---|
| 코퍼스 내 `[asy]` 비율 | 13.6% |
| **검색 상위 5건 내 `[asy]` 비율** | **21.0%** (21/100) |
| 평균 유사도 — 그림 포함 / 미포함 | **0.3773 / 0.3935** |

그림 코드가 섞인 청크는 **덜 걸리는 게 아니라 오히려 자주 걸리고**(13.6% → 21.0%),
유사도 차이도 0.016 으로 작다. 그 청크가 평균 963자로 더 길어 **주제를 더 많이 담는 효과와 구분되지 않으므로**,
확정하려면 `[asy]` 블록을 제거한 코퍼스로 같은 질문셋을 다시 재야 한다.

→ 문서에는 **"유력 후보이나 미확정"** 까지만 적고, 확정 절차를 `details` 에 명시.

**`ai-4` 의 진단 전제와 실제 데이터의 불일치 (사용자 확인으로 확정)**

`ai-4` 는 원인을 *"영어 강의자료 + 한국어 질문 조합에서 유사도 분포가 낮게 깔림"* 으로 진단.
**사용자 확인 결과 영어 자료는 처음부터 부재** — 코퍼스 교체로 전제가 사라진 것이 아니라
**진단 당시에 이미 틀린 전제**였다. 자료를 열어 보지 않고 원인을 언어 축으로 단정한 것.
현재 벡터 스토어 5,799건의 구성은 아래와 같다.

| source | 건수 | 언어 |
|---|---|---|
| `MATH-ko-test.jsonl` | 5,295 | **한국어** |
| `ko_math-500.jsonl` | 500 | **한국어** |
| `math-formula-{1,3,5,6}.pdf` | 4 | 영어 |

**영어 자료는 4청크(0.07%)뿐이고 코퍼스는 사실상 전부 한국어.**
그럼에도 한국어 질문의 최고 유사도가 중앙값 0.40 에 그친다 —
**즉 낮은 유사도의 원인은 다국어 정렬이 아니다.** 같은 언어끼리도 0.4 대가 나오는 것은
질문(자연어 요청)과 문서(문제 + 풀이 본문)의 **형식이 다르기 때문**으로 보이며, 이는 청킹·문서 형식 축.
`ai-4` 가 스스로 *"가장 큰 공백"* 이라 적은 청킹 미검토와 같은 방향.

→ 문서를 이에 맞게 수정 완료. 새 원인은 **단정하지 않고 유력 후보(그림 소스 코드)까지만** 적었다 — 위 A-3 보강 참조.
