## 4. SVG 에 대한 판단 — 교체 불필요 (제안만)

현재 `viz-frame` SVG(2단 방어 도해)는 **여전히 정확하다.** Redis 선점 게이트 → DB 낙관적 락, 부족 시 조기 차단, 미초기화 시 DB 폴백 — 셋 다 코드와 일치하고 이번 재작성으로 부정된 내용이 없다. **바꾸지 않는 것을 권한다.**

굳이 보강한다면 아래 두 가지인데, 둘 다 이번 서술의 핵심(정합성 vs 완주율 분리)을 도해가 이미 설명하지 않는 영역이라 **정보 밀도 대비 이득이 작다.**

1. `@Retryable(3, 100ms)` 라벨 옆에 재시도 소진 → `@Recover` → 409 로 빠지는 화살표를 추가해 "확정된 실패 경로"를 시각화. 다만 도해가 좌→우 정상 경로 서사인데 예외 분기가 들어가면 축이 흐려진다.
2. 별도 SVG로 "재시도 횟수 ↔ 완주율 수익 체감 곡선"을 추가. 다만 이 곡선의 y축이 곧 **재현되지 않는 완주율 절대값**이라, 쓰지 않기로 한 수치를 그림으로 되살리는 셈이 된다. **권하지 않는다.**

바꾸기로 한다면 기존 관례를 따를 것:
- 박스 `fill:rgba(67,97,184,0.10); stroke:#4361b8` 계열, 제목 `fill:#1a1a2e`, 보조 `fill:#6b7280`, 라인 `stroke:#9ca3af`
- `viewBox` + `width="100%"`
- 클래스·marker id 접두사는 기존 `sk-` / `pg-` / `ks-` / `cp-` / `c5-` 와 겹치지 않게 (예: `st2-`)
