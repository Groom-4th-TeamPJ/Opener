# 포트폴리오 논리 흐름 평가 (문서 단독 기준)

대상 : `backend/docs/portfolio/PORTFOLIO.html` 전체 15개 섹션 · 3개 파트
일자 : 2026-08-16
전제 : **코드 구현 여부는 판정 대상에서 제외.** 미구현·미설계 항목도 향후 구현 가능한 것으로 두고, 문서를 처음 읽는 사람에게 서사와 주장이 성립하는지만 평가
성격 : 평가 보고. 수정 지시가 없으므로 문서는 미변경

---

## 0. 총평

**구조는 튼튼하고, 무너지는 곳은 섹션 내부의 회수율.**

15개 섹션 전부 `[기능·개선] → 전체 아키텍처 → 문제 원인 및 한계점 → 해결 과정 → 결과` 4단을 지킴. 이 일관성 덕분에 어느 섹션을 펼쳐도 읽는 순서를 다시 배울 필요가 부재. 대안 비교와 선택 근거가 대부분의 섹션에 존재하는 것도 강점.

무너지는 지점은 **문제로 제기한 것과 결과로 회수한 것의 불일치**. 심한 섹션은 문제 2개에 결과 8개.

---

## 1. 강점 (유지할 것)

### (1) 대안을 세워 놓고 고른 흔적이 거의 모든 섹션에 존재

- 조회 경로 — "N+1 처방 후보 넷을 성질로 갈라 비교"
- 추첨 예약 — "예약을 어디에 둘지부터 후보 셋을 성질로 갈라 비교"
- 배포 — "두 서버를 가르는 방법 셋 중 경로 라우팅을 선택"
- 재고 차감 — "세 전략을 같은 조건에 세우기 위해 차감 전략을 인터페이스로 분리"

면접에서 가장 강한 재료. "왜 그것을 골랐나"에 즉답이 되는 구조.

### (2) 자기 반증을 서술 안에 남김

- RAG — "그 진단은 적재 코퍼스를 열어 보지 않고 세운 전제"
- 선착순 쿠폰 — "부하로 확인한 것은 그 락이 대가만큼의 보장도 못 준다는 사실"
- 재고 차감 — "첫 측정에서는 둘 다 좋아진 것처럼 보였으나 두 런의 VU가 달라 섞여 있던 값"
- 세션 저장소 — Hash Tag 를 "겪은 장애를 고친 게 아니라 선제 조치"로 자기 한정

과대 주장을 스스로 깎는 서술은 나머지 주장의 신뢰를 올림.

### (3) 한계를 결과에 남기는 규율

- 추첨 예약 — "지연 상한이 폴링 주기라는 것을 설계 성질로 확정"
- RAG — "일반 채팅 경로에 Timer가 없어 … 답변 불가"
- 선착순 쿠폰 — "다만 장애 내성까지 확보하지는 못한 상태"

**구현되지 않은 것을 구현되지 않았다고 쓰는 것 자체가 논리적 미덕.** 이 평가의 전제(미구현 허용)와도 부합.

## 2. 문제 — 우선순위 높음

### (A) 문제 개수와 결과 개수의 불일치 — 회수율 붕괴

| 섹션 | 문제 | 해결 | 결과 | 판정 |
|---|---|---|---|---|
| 4. 채팅 영속화 | 4 | 7 | 4 | **모범** — "비었다 두 뜻" → "판정 근거 적재" → "세 사유로 갈린 지표" 가 1:1 |
| 3. 채팅 세션 저장소 | 4 | 8 | 7 | 양호 — 결과가 많으나 전부 문제로 소급 가능 |
| 2. RAG 검색 | **2** | 9 | **8** | **붕괴** — 아래 상술 |
| 7. 조회 경로 데이터 모델 | 3 | 5 | **2** | 문제 3개 중 스크랩북 필터 조회가 결과에서 미회수 |
| 6. 인증·세션 방어선 | 3 | 9 | 4 | 결과의 "설정 바인딩 분리 검증"에 대응하는 문제가 부재 |

**RAG 섹션의 구조**

문제로 제기된 것은 둘뿐 — ① Hallucination 위험 ② 임계값 0.7 에서 검색 0건.

그런데 결과에 등장하는 것은 여덟 — 근거 없는 응답 감소, 임계값 스윕, 스위치 결론, 두 경로 벡터 검색 비용 동일, 검색 0건 폴백, 초기 진단 반증, 자료 형식이 유력 원인, Timer 부재로 답변 불가.

**Feature Flag 짝 구현체 · 히스토리 윈도우 비용 통제 · 두 경로 검색 비용**은 문제 섹션에 대응 항목이 전무. 독자 입장에서는 *묻지 않은 질문에 답이 돌아오는* 구조.

→ 처방 : 문제 섹션에 "플래그를 끄면 기동 자체가 실패" · "히스토리 전량 주입으로 프롬프트 비용이 턴마다 증가" 두 항목을 추가. 해결·결과는 그대로 두고 문제만 보강하면 회수율이 맞음.

### (B) RAG 섹션의 서사가 자기 부정으로 종결

현재 흐름은 다음 순서.

1. 임계값 0.7 에서 검색 0건 → 0.2 로 낮춰 해소
2. 당시 진단은 "한국어 질문 vs 영어 중심 임베딩 모델의 언어 정렬"
3. 그 진단은 코퍼스를 열어 보지 않고 세운 전제
4. 스윕 실측이 그 진단을 반증
5. 유력 원인은 자료의 형식
6. 일반 채팅 경로 비용은 답변 불가

정직함은 강점이나 **읽고 나면 무엇을 해냈는지가 남지 않음.** 실제 성과(스윕으로 원인 규명 · 플래그 양방향 기동 확보 · 검색 0건 폴백)가 자기 반증에 묻힘.

→ 처방 : 순서를 뒤집어 **"무엇을 확립했는가"를 먼저 세우고, 그 과정에서 초기 진단이 실측으로 반증된 사실을 뒤에 배치.** 같은 정직함을 유지하면서 성과가 남음.

### (C) 1번 섹션이 4번 섹션의 결론을 선점

「1. 실시간 AI 튜터링 채팅 파이프라인」의 해결 마지막 항목이 "저장 경로를 응답 경로에서 분리해 전용 큐로 발행하고 Consumer 가 Redis 조회·검증·PostgreSQL 적재", 결과 마지막이 "유실 경로 3종을 서로 다른 카운터로 분리해 사유별 추적이 성립".

이 둘은 **「4. 채팅 영속화 파이프라인」의 주제 그 자체.** 독자가 4번에 도달했을 때 이미 결론을 읽은 상태라 새로움이 감소.

같은 현상이 「3. 채팅 세션 저장소」 결과 마지막("내구성 대신 감지를 확보")에도 존재.

→ 판단 : 같은 시스템을 다루므로 겹침 자체는 불가피. 다만 **같은 사실이 세 섹션에서 각각 결론처럼 제시되면 "이건 몇 번의 성과인가"가 흐려짐.** 1번에서는 "저장 경로를 분리했다"까지만 두고 사유별 카운터는 4번에 넘기는 편이 각 섹션의 소유가 분명해짐. (3번의 감지 항목은 해결 8번의 주장을 회수하는 자리라 유지가 타당)

### (D) 1번 섹션의 주제 과부하

해결 과정 8개가 서로 다른 문제를 다룸 — 스레드 고갈 · 일괄 전달 · 아키텍처 선택(WebFlux 전면 vs 하이브리드) · 스케줄러 · 연결 관리 · 저장·표시 정합 · 상류 구독 누수 · 큐 분리.

반면 상단 개선 요약은 "스레드 고갈과 일괄 전달을 두 단계로 나눠 해소하고, 상류 구독 누수까지 차단" 셋만 언급. **나머지 다섯이 요약에서 탈락.**

→ 처방 : 요약을 늘리기보다 섹션을 가르는 쪽이 나음. "실시간 전달 구조"(스레드·전달·아키텍처 선택)와 "연결 생명주기"(연결 관리·구독 누수·정합)는 문제의 성질이 다름.

## 3. 문제 — 우선순위 중간

### (E) 개선 요약의 층위가 섹션마다 다름

| 섹션 | 요약 | 층위 |
|---|---|---|
| 4. 영속화 | "세 사유로 갈라 관측 가능하게 전환" | **결과** — 좋음 |
| 3. 세션 저장소 | "읽기와 쓰기의 책임을 갈라(CQRS) 지점별로 라우팅" | 수단 |
| 12. 배포·라우팅 | "Nginx 경로 라우팅 + Compose·CI/CD 로 해결" | 도구 나열 |
| 13. JWT 무효화 | "두 단위를 한 검증 경로로 통합" | **결과** — 좋음 |

요약은 목차에서 먼저 읽히는 문장. **무엇을 썼는가(수단)가 아니라 무엇이 달라졌는가(결과)로 통일**하는 편이 스캔에 유리.

### (F) 결과의 수치 밀도 편차

수치가 조밀한 섹션(세션 저장소 · 선착순 쿠폰 · 재고 차감)과 정성 서술만 있는 섹션(조회 경로 데이터 모델 · 배포·라우팅)이 공존.

「7. 조회 경로」 결과 2개는 "추가 쿼리가 구조적으로 미발생" · "그래프 탐색 경로로 성립" 으로 둘 다 정성. 면접관은 여기서 "그래서 몇 ms 줄었나요"를 물음.

→ 처방 : 측정하지 않았다면 **다른 섹션에서 하듯 "미측정"을 명시.** 이 문서는 이미 "답변 불가"를 쓰는 규율이 있으므로 같은 방식이 자연스러움. 정성 서술만 두는 것보다 미측정 명시가 신뢰에 유리.

## 4. 문제 — 우선순위 낮음

### (G) "문제 원인"에 원인이 아닌 배경이 섞임

- 「11. 위치 공유」 첫 항목 "폴링 방식은 불필요한 요청과 지연을 유발" — 겪은 문제가 아니라 요구사항
- 「13. JWT 무효화」 첫 항목 "JWT 는 서명만 맞으면 통과하는 무상태 구조" — 기술 설명

배경 항목이 앞에 오면 뒤의 해결과 인과가 느슨해짐. 다만 도입부 역할을 하므로 치명적이지는 않음.

### (H) 파트 간 연결이 문서 끝에 하나뿐

세 프로젝트가 병렬 나열이고, 유일한 연결 문장이 **마지막 섹션의 마지막 결과** — "여기서 드러난 키 설계의 한계가 다음 프로젝트의 설계를 전환".

이 문장은 성장 서사의 핵심인데 가장 늦게 읽히는 자리에 존재. 문서 앞쪽에 같은 연결을 한 번 세워 두면 세 파트가 나열이 아니라 순서로 읽힘.

## 5. 정리

| 항목 | 성격 | 우선순위 |
|---|---|---|
| (A) 문제·결과 회수율 불일치 (특히 RAG) | 구조 | 높음 |
| (B) RAG 서사가 자기 부정으로 종결 | 서사 | 높음 |
| (C) 1번이 4번의 결론을 선점 | 구조 | 높음 |
| (D) 1번 섹션 주제 과부하 | 구조 | 높음 |
| (E) 개선 요약의 층위 불일치 | 표현 | 중간 |
| (F) 결과 수치 밀도 편차 | 근거 | 중간 |
| (G) 문제 섹션에 배경 혼재 | 표현 | 낮음 |
| (H) 파트 간 연결 부재 | 서사 | 낮음 |

**가장 적은 손으로 가장 크게 좋아지는 것은 (A)** — 해결·결과를 건드리지 않고 **문제 섹션에 항목만 추가**하면 회수율이 맞음. (B) 는 문단 순서 교체라 분량 변화 부재.
